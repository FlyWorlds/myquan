# Q51 7.4.0 交付包

## 2026-08-08 文档修订：`get_restricted_list` 套餐配额降级

本次修订不改变 `data_version=7.4.0`、`schema_version=2.0.0`、评分规则、承保门或生产 Parquet 的历史内容；它补充了限售股解禁接口发生套餐配额限制时的明确降级契约。

- 将“限额 / 套餐 / quota / rate limit”统一记录为 `quota_or_rate_limit`，按 `max_api_attempts` 有界重试，默认 2 次、允许 1–4 次。
- 重试耗尽后写入 `coverage_gap` 与 `insufficient_evidence`，保留安全失败分类、异常类型和尝试次数，不保留服务端原文或凭证。
- 定增解禁风险链路不从空返回中推导“无解禁”，不生成或刷新 `private_placement_supply_risk`；风险榜没有定增卡不代表没有供给压力。
- `research_digest` 标记部分覆盖，P4 健康报告通过 `coverage_gaps` 和 `coverage_gap` 告警提示消费者；其他事件类别可继续按其独立接口运行。
- 配额恢复后重新运行全市场、点时一致的扫描；不得自动切换第三方数据源、手工填零或将旧快照拼入当前决策日。

## 交付内容

- 开发产物：Skill 说明、Panda Data 接口指南、实现、测试和演示视频。
- 生产产物：生产读取规则和全 A 股 Parquet 快照。
- 验证材料：生产看板、离线讲解页、录制讲稿和运行健康记录。

## 验收

解压 Release 附件后，在根目录运行：

```powershell
python 开发产物\scripts\test.py
python 开发产物\scripts\validate_build.py
```

第二条命令检查开发包同步、生产 Parquet、版本、主键、JSON、研究摘要边界和生产健康状态。真实生产扫描发生 `get_restricted_list` 配额限制时，还应检查当前快照的 `coverage_gap` 记录与 `validation/operations/health_latest.json`，不得只依赖结构校验结果。
