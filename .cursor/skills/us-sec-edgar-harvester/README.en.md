## 📖 What This Is

`us-sec-edgar-harvester` is a **pure information-collection** skill. Given a US-listed ticker,
an insider (a Form 4 reporting owner), or an institutional manager (a 13F filer), it pulls the
**primary public filings** from SEC EDGAR, parses the key structured fields, deduplicates by
accession number, resolves `/A` amendment supersede chains, and produces a **sourced, dated
filing timeline plus a structured dataset**.

It reads **SEC EDGAR public endpoints only**: full-text search (efts.sec.gov), the submissions
API (data.sec.gov), the ticker→CIK map, and the Archives filing index/documents. The skill
supplies the endpoint list, field maps, and rules; the actual HTTP is delegated to the
runtime's web/fetch capability.

**How it differs from sibling repos:** `hk-us-insider-radar` and `hk-us-holder-concentration`
use the **Pandadata vendor feed** (normalized, cross-market, key-gated). This skill uses the
**primary SEC public source**, keeping accession-level provenance. Use this one for citable raw
EDGAR filings; use the Pandadata skills for the vendor's normalized feed.

**Input:** ticker / company / insider / manager + form types + date window.
**Output:** `filings_dataset.csv` (one row per filing or per Form 4 transaction),
`filing_timeline.md` (timeline with accession numbers), and a facts-only coverage summary.

## 🚀 Quick Start

```bash
# Copy into the Claude Code skills dir (other runtimes: see Runtime Compatibility)
cp -r skill-us-sec-edgar-harvester ~/.claude/skills/us-sec-edgar-harvester
```

Example trigger prompts:

```text
Harvest AAPL 8-K and Form 4 filings from the last 90 days into a sourced timeline
Collect Tesla insider (Form 4) open-market P/S transactions over the past year, deduped
Pull a fund's latest 13F holdings from EDGAR and label the reporting period
```

Self-check a produced report:

```bash
python scripts/validate_report.py path/to/filing_timeline.md
```

## 🌐 Data Sources & Dependencies

- **EDGAR full-text search:** `https://efts.sec.gov/LATEST/search-index`
- **EDGAR submissions API:** `https://data.sec.gov/submissions/CIK##########.json`
- **Ticker→CIK map:** `https://www.sec.gov/files/company_tickers.json`
- **Filing index & documents:** `https://www.sec.gov/Archives/edgar/data/<cik>/<accession>/`

All are public, no-key SEC endpoints. Requests are delegated to the runtime's web/fetch
capability; no API key is bundled. See `references/edgar-sources.md` and
`references/methodology.md`.

## ⚠️ Limits & Risk Boundary

- **Collection only:** harvests and structures public facts. It does **not** score, rank,
  value, forecast, or recommend.
- **Public SEC data only:** ships no keys; must send a **descriptive generic User-Agent** per
  SEC fair-access policy — never a secret, never someone else's private contact (unless the
  user supplies their own).
- **Rate limits & degradation:** respect the SEC cap (~10 req/s, throttle in practice); on
  403/429 back off and **report partial coverage** rather than dropping data silently.
- **Date semantics:** filing/acceptance date ≠ event/period date; every row labels which it uses.
- **Amendments:** `/A` supersedes the original; both are kept with the supersede chain.
- **Form 4 codes:** `P/S/A/M/F/G/...` recorded verbatim; grants/withholdings are not collapsed
  into a "buy".
- **13F lag:** filed up to 45 days after quarter end, US long positions only — stale by design.
- **Human confirmation:** any external write (send, publish, order) needs an explicit user
  trigger; this skill performs none of those.
