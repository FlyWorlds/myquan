# 收益日历与16b分组

- 顶部“收益日历”读取 `/api/holdings/returns-calendar?year=2026`，由 Python 转发 Java 后端。SQL 从 `paper_account_snapshots` 取每个交易日最后一条估值，不把分钟快照相加。缺失日收益保留为空。已有异步账户估值写入流程继续负责落库，页面不写交易账本。
- 日/月日历、柱状图、金额/收益率切换；月金额为有记录日收益之和，月收益率为有记录日收益率的复合值。历史快照不足不回填假数据。
- 16b 筛选后输入组名保存。V8 的 `strategy_selection_groups` 保存参数、原始池子和展示选股，参数化 SQL；每次保存创建独立分组，重名不会覆盖已有记录。载入会恢复页面参数及当前后台16b监控池。
- 选择已保存分组，点击“回测近7天（1分钟）”才启动后台任务。模块导入及分组列表读取均不拉分钟行情。
- 窗口为上海时间最近7个自然日（含当天）。复用已有分钟拉取器（Pandadata/akshare）及组合模拟器，四槽、30万、25%单槽，因子26 half_gain、项目既有费用与T+1规则。
- 每只股票显示数据起止、条数和交易日数量。缺少分钟或前置日线则整次任务失败，不跳过股票。供应商只提供部分交易日时，结果只代表实际覆盖，不能解释成完整7个交易日收益。
- 保存池子来自当前筛选，历史回放存在当前池子选择偏差，不是历史时点无前视选股。回测为研究回放，不写交易状态。
- 任务进度/结果保存在进程内，重启后丢失；分组保存在MySQL中，重启后可重新载入。一次只允许一个回测任务，接口轮询不会重新拉行情。

验证：Java 37项测试；Python测试确认导入不拉行情、点击才建线程；Nuxt生产构建通过；本机MySQL成功应用V8迁移并验证日历按日去重查询。未自动执行真实市场行情回测，遵守点击后才拉取要求。

## 默认分组（V9）

“设为默认”将选中分组记录在 `strategy_selection_preferences` 的单行配置中，并立即载入。每次进入页面时先读取数据库配置，再调用分组载入接口恢复股票列表与筛选条件。默认配置不依赖浏览器缓存，重启后仍有效；不触发回测或分钟行情拉取。设置默认使用事务锁和外键校验，不存在的分组不会替换原默认值。

筛选区参考 PandaAI 的黑白按钮层级、圆角卡片与分区操作：保存当前结果、载入保存分组、回测分别呈现；明确显示当前载入和默认分组，并提供操作进度、成功反馈、失败重试及空状态。
