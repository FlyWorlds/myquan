# 策略16数据库收益账本

## 范围

策略池的虚拟买卖账本与实际Paper账户分开。每个标的独立使用原有10万元初始虚拟资金，买入沿用95%资金、100股整手，不受实际账户每日新增2只/总槽位5只约束。这里不是整个股票池的资金加权组合回测收益，也不影响真实模拟盘现金。

实时链路只使用准备好的过门/开盘条件与新鲜报价，因子26卖出复用报价纯函数；不使用1分钟K线，不在展示线程回放历史，不按价格变化重写已确认成交。实际账户和策略账本分别排队执行，策略数据库慢不会阻塞实际账户下单队列。

2026-10-15复审后，行情先保存 `market_quote_latest` 并确认，再通知实际账户与虚拟策略队列计算。页面和估值读已入库报价缓存；迟到的正式收盘快照在非交易时段可以更新估值，但不能改峰值/止损状态或补造成交。行情库不可用时阻断新执行，不把接收时间当成供应商时间，也不刷新旧报价的年龄。

## 收益定义

| 字段 | 金额与百分比 |
| --- | --- |
| 累计策略盈亏 | 策略现金＋剩余数量×数据库估值价－策略初始资金；等于历次已实现＋当前浮盈 |
| 累计收益率 | 累计盈亏÷该标的策略初始资金，不是股价涨幅，也不是多次买入金额之和作分母 |
| 持有时单笔盈亏 | 剩余数量×（数据库估值价－本次买入价）；百分比为（估值价－买入价）÷买入价 |
| 综合本轮盈亏 | 本轮全部卖出腿已实现盈亏＋剩余浮盈；百分比除以本轮原始买入成本 |
| 全清后的单笔 | 冻结综合本轮成交盈亏，之后股价变化不影响已经平仓的收益 |
| 入库后增量盈亏 | 当前累计盈亏减迁移时检查点盈亏，单独保留；不证明检查点以前的交易正确 |

例：10元买1000股，11元卖400股，现价12元。已实现400元，剩余浮盈1200元；综合本轮1600元/10000元=16%，当前持有价差20%。若初始资金10万元，累计策略收益为1.6%。不能把最后一次卖出价相对买价的涨幅当综合盈亏。

以上沿用旧策略虚拟账本零费用模型；不代表实际券商扣税费后的收益。实际Paper交割另有独立口径。

## 数据与接口

- `strategy_symbol_books`：每标的一行当前策略状态、现金、数量、估值、累计与本轮收益、版本。
- `strategy_symbol_events`：新BUY/SELL不可变逐笔记录，包含成本、该卖出腿已实现盈亏、成交后数量/现金及账本版本。按版本排序，不能用同秒时间戳或随机ID推断先后。
- `strategy_legacy_checkpoints`：原本地JSON原样保存、哈希标识，不伪造成交。

迁移V5/V6自动由Flyway执行。读：`GET /api/strategy-books/strategy16`；成交/估值：`POST /api/strategy-books/strategy16/{code}`；逐笔查询：`GET /api/strategy-books/strategy16/{code}/events`。数据经Java事务写MySQL，使用十进制定点计算；版本冲突、重复请求、超卖、同日T+1卖出、乱序报价拒绝或幂等，不回退本地文件。

MARK只更新当前估值和最后请求标记，不往成交表逐条堆行情；价格不变不反复写，普通估值最多每标的每秒一次，成交优先立即提交。需要完整逐报价回放仍须独立归档，不能从这些收益快照反推分钟内路径。
