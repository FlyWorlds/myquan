# 策略16价格与时效复审

## 当前链路

优先接收实时报价 → 有界队列 → Java/MySQL最新事实快照确认 → 按原接收顺序分发 → 实际账户/独立策略分别计算 → 版本化成交与收益入库 → 页面读取已确认报价和账本。

报价回调不请求数据库、不拉分钟线。最新报价表是 `market_quote_latest`，接口为Java的 `GET/POST /api/market-quotes`；V7迁移在受控启动Java时创建。原始接收时间跨越写库和执行队列保留，数据库回执不能把旧报价变成新报价。

## 已修复问题

| 风险 | 修复与验证 |
| --- | --- |
| SSE将接收时刻当成供应商行情时间 | 未核验源时间的SSE仅原始展示/连接健康，不发出可执行事件；可信报价有独立OHLC/竞价路径，避免SSE污染正式开盘和阈值。当前策略16只持久化并消费新浪源时间快照 |
| 旧报价跨源覆盖新报价 | 源时间较旧的快照不回滚执行缓存；MySQL按源时间、原接收时间和版本拒绝倒退，重复请求不重复推进版本 |
| 正式开盘后原始open/high/low缺失，被兜底价冒充正式行情 | 9:25后缺失原始OHLC或源日期/时间只保留展示，不送交易/报价数据库；竞价前指示价仍与正式价隔离 |
| 全部批次返回后才发布前面报价 | 实际持仓优先；首批50只独立轮询，其余最多3组。每批返回立即分发，实时请求连接/读取超时分别2/3秒，旧的通用调用保留原默认超时 |
| 等待平仓/资金计算后仍使用旧now | 平仓后、候选处理及实际成交前重新取时间，源时间或原接收时间超过5秒拒绝成交 |
| 数据库或执行队列积压 | 两层有界队列，写库队列超过5秒丢弃，执行队列过期也丢弃并计数；不历史补单、不本地回退 |
| 把峰值/触买事件合并掉 | 同一标的同批多个实收价格按序确认和分发，不能只取最后一价；关键峰值/止损状态不受纯估值写入节流影响 |
| 重启复核后复用此前快照 | 恢复订单在首次重新核验时更新武装时间和源报价边界，不能以核验前的报价补成交 |
| 预备竞价开盘单被盘中刷新覆盖 | 独立策略账本与实际账户一致保留预备开盘单至09:30:05；新禁买审核优先，不能保留危险订单 |
| 只读刷新伪造信号已刷新 | 页面刷新/行情展示不再推进signalUpdatedAt；只有成功处理新鲜事件的执行器推进，积压/过期/失败不推进 |
| 写库时只信客户端旧decisionAt | Java新实时成交按服务器时钟检查报价是否过期，事务中修改后再检查；超时回滚现金/持仓/流水。已提交请求重试先幂等解析，不二次成交 |
| 收盘后估值仍依赖5秒内新成交 | 已确认的正式收盘快照在非交易时段只可MARK估值，不升峰值、不改止损状态、不买卖；连续竞价期间旧收盘快照仍不可用 |
| 旧Java与新Python不匹配 | 启动器替换Python前检查行情数据库接口，缺失则提示先替换Java并保留现有Python；Python进程统一TZ=Asia/Shanghai |

## 价格口径

- 开盘突破买点继续使用现有向上取合法价位规则：14.83元开盘、2.5%阈值对应15.21元；15.20不触发，15.21触发。
- 必须是实收现价达到挂单价，今日最高曾越过但现价未到不算本次触发；开盘修正不一致、OHLC不自洽、未核定开盘、缺失/未来/过期源时间均不能成交。
- 仍保留用户指定的模拟假设：挂单10.25、实收现价10.80时按10.25模拟成交，同时记录10.80。它不是券商真实撮合价，也没有成交量/排队/滑点保证。
- 原首次触发时间与实际用于执行的报价时间分开：新增 `execution_quote_time`、`execution_received_at`、`observed_price`、`quote_age_ms`、`queue_age_ms`、`quote_db_revision`、`quote_db_at`，成交流水和交割记录保留这些证据。

## 时效边界

5秒是拒绝过期的上限，不是“5秒内必成交”或端到端延迟保证。行情源、轮询等待、网络往返、写库、执行队列、账户事务、UI刷新均会增加延迟；源时间只有秒精度，无法证明真实逐笔先后。首批独立、0.1秒写库检查间隔和有界超时只是工程配置，不是测得的p95。

快照 `quoteStorage` 提供报价库就绪/错误、待处理数、拒绝/过期/丢弃计数、最近写入往返时间及真实源时间年龄；`executionStatus` 提供执行队列、失败/过期计数及最后有效评估时间。连续竞价时，即便SSE仍连接，已入库报价过期或写库失败也不能显示交易行情健康。
