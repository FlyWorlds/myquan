## 实时链路

行情源 -> QuoteHub可信时间/展示隔离 -> 有界持久化队列 -> Java批量确认 `market_quote_latest` -> 已确认报价缓存/执行队列 -> 买卖及收益计算 -> Java版本校验事务 -> MySQL。

报价写入与交易执行分线程：先拉取实时数据，再确认事实快照入库，然后消费已确认的报价；不是页面每次请求都同步查询MySQL，也不是等分钟线回放。单批最多64个观测事件、写入线程空闲检查间隔0.1秒，队列满/积压超过5秒明确丢弃计数，不事后补造成交。相同标的同批连续价格均返回独立确认版本，不能只留最后一价再执行。最新表仅保存每股最近快照，完整报价事件归档另列TODO。

当前SSE路径用本机接收时刻，没有已核验的供应商源时间，故只作原始展示/连接健康；与新浪源时间快照使用独立OHLC和竞价路径缓存，不能污染交易的正式开盘、峰值或买点。列表、持仓估值和观察池在报价驱动模式读已入库缓存。新浪首批50只（实际持仓优先）独立轮询，其余最多3组后台轮询，单个冷批慢不再阻塞首批。

新实时成交要求源时间及最初接收时间均在5秒内；数据库回执不重置接收时间，等待平仓、资金计算后再次核查。Java在事务内对新成交按服务端时钟二次检查，已提交请求的幂等重试先返回原结果，不二次成交。迟到收盘价只允许在非交易时段更新估值，不改变峰值、止损状态或补买卖。报价库和交易服务未热替换；V7待受控启动Java后生效。

行情回调只入队，不请求数据库。展示读同一版本的账户与缓存报价，不调用分钟回放、不结算买卖、不修改策略历史账本。日线、正式开盘复核、其它策略面板与指数后台更新。

条件单保存在账户JSON的`condition_buy_orders`；持仓增加`quote_exit_session`、`quote_session_peak`、`quote_exit_watermark`，沿用现有数据库接口，无需清库/重导持仓。峰值/阶段/成交等状态变化才写账户，不逐报价保存完整账户；独立行情事件表尚未建设。

## 买入

1. 9:25后，正式开盘可用、日线覆盖上一完整交易日且过门、独立开盘复核通过，才准备条件单。
2. 重启后的挂单必须重新复核，不能以复核当条报价直接成交；开盘变化重新准备。
3. 9:30后新鲜现价>=挂单价，且挂单价落在真实日内价格范围内，才竞争入槽；日内最高超过但现价未到不补记。
4. 按首次接收触发顺序竞争，校验新增数量/槽位/现金/持仓估值/已卖限制/封板；订单和买入记录同次落库。
5. 因子29开盘撮合（策略一/十六）只允许开盘前已准备、9:30:05前收到的新鲜报价，不用迟到报价回填开盘成交。未武装时条件单仍走因子26 开盘突破。

竞价过滤：正式开盘距该股票涨停幅度不足0.3个百分点即禁买，普通主板9.7%、20%股票19.7%。这是近涨停排除规则，不是全天一字板证明；免费报价不能证明真实排队成交。

## 卖出

`eval_factor26_quote`复用因子26纯公式，只输入观测现价，不构造/拉取分钟K，不采用分钟内高低先后假设。保留硬保护、日频波动回落、10%半仓、15%全清、峰值回落和T+1。日频波动从缓存的前日及更早日线计算；缺失沿用原公式无波动参数分支，不在成交线程联网补数据。

- 下穿保护跳价按收到的现价模拟成交，不能保证保护价成交。
- 上行阶梯保留原目标价成交假设；开盘保护只在开盘附近基于新鲜连续竞价报价与冻结隔夜峰值，保留原开盘价纸面成交假设。
- 买入当日不卖，已半仓不能重复减半；后续报价可以全清剩余数量。
- `signal_time`记录行情时刻，`decision_time`及成交时间记录实际处理时间，不将迟到报价伪装成刚刷新。
- 重复、逆序、未来、过期、排队超过5秒的报价不能补造过去成交。断线漏掉的路径未知，重启只恢复已提交的峰值和阶段。
